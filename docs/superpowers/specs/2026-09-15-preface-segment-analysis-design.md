# 前贴片段后台补全分析设计

## 目标

将母版“补全分析”从整条素材重跑改为前贴资产级后台任务。任务提交后不依赖弹窗或页面存活，并支持在母版库一键补全所有分析不完整且有视频源的前贴。

## 用户体验

- 单个母版详情中的“补全分析”仅提交当前母版任务；提交成功后允许立即关闭弹窗或离开页面。
- 母版库标题区增加“一键补全分析（N）”，N 为当前分析不完整且可处理的前贴数。
- 卡片和详情显示持久化状态：待补全、排队中、分析中、已完成、失败、无视频源。
- 批量提交只处理分析不完整的 AI 前贴；完整项跳过，已排队或正在运行的项不重复创建任务。
- 任务失败后允许重新提交；无视频源时给出明确原因。

## 分析范围

- 每个任务必须保存 `clip_start_seconds` 与 `clip_end_seconds` 快照。
- 有独立 `media_file` 时，只分析该剪辑文件的 0 至剪辑时长。
- 没有独立剪辑但源素材有视频时，先按资产的起止秒数裁切临时文件，再分析临时文件。
- 语义模型、抽帧、ASR、OCR 均不得接收整条源素材。
- 结果中的 `scope` 记录源素材坐标，证据时间码转换回源素材坐标后才能写入资产。
- 不覆盖 `ad_materials.analysis_result`，只更新对应 `material_library_assets.analysis_result` 与 `prompt_blueprint`。

## 数据与任务模型

新增 `preface_analysis_jobs`：关联前贴资产与源素材，持久化起止秒数、状态、进度、重试、租约、错误、结果及幂等键。数据库唯一索引保证一个资产同一分析版本最多只有一个有效任务。

新增前贴分析接口：

- `POST /api/lumina/preface-analysis/assets/{id}/enqueue`：单条提交。
- `POST /api/lumina/preface-analysis/enqueue-incomplete`：批量提交所有可处理的不完整项。
- `POST /api/lumina/preface-analysis/claim`：Worker 领取任务。
- `PATCH /api/lumina/preface-analysis/jobs/{id}`：Worker 上报进度和结果。

列表接口通过资产展开最新任务，前端刷新或重新进入后可以恢复任务状态。

## 完整性规则

前贴分析至少应提供：题材标签、人物关系、创作思路、开场动作/钩子、复刻机制、正片承接方向。完整性判断由共享函数完成，批量接口与界面使用同一规则。

## 边界与失败处理

- `clip_end_seconds <= clip_start_seconds`：拒绝入队并显示片段范围无效。
- 没有资产视频且没有源视频：标记无视频源并跳过。
- 已排队或运行：返回现有任务，不重复创建。
- 已完成且结果完整：批量操作跳过；单条按钮不显示。
- Worker 失败：保留错误与进度，允许用户重试并生成新的分析版本幂等键。

## 验收标准

- 提交单条任务后关闭弹窗、刷新或离开页面，后台任务继续；再次进入可见真实状态。
- 一键补全只排队缺失分析且有视频源的 AI 前贴，并返回已提交、处理中、已跳过、无视频源数量。
- Worker 实际输入媒体时长等于资产区间时长，不读取区间以外画面、语音或文字。
- 完成后只更新对应母版，原素材全片分析保持不变。
- 所有新增后端契约、范围转换、前端按钮和状态恢复均有自动化测试。
